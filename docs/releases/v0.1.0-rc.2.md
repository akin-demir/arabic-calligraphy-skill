# v0.1.0-rc.2 — Diwani typography

RC2 adds **Layla Diwani Regular 2.0** by Mohammed Isam to the existing Naskh, modern Kufi and Nastaliq workflows. All four are font-based approximations, with no expert authenticity certification. There are twenty catalog entries: four implemented and sixteen reference-only.

## New in this candidate

- `--style diwani` renders unvocalized Arabic headings, names and wordmarks to PNG and outlined SVG.
- Diwani posters with a Naskh supporting line, plus real generated examples and visual regression evidence.
- The original OFL font is bundled unchanged with notices, author credit, FONTLOG, pinned source and SHA-256 validation.
- 470 automated tests, including 89 unmarked corpus inputs for Diwani and explicit boundary/refusal tests.
- More precise skill instructions distinguish modern Kufi from Square Kufic and require reporting a missing renderer rather than inventing a substitute.
- A ready-to-upload `arabic-calligraphy-skill-rc2.zip` is now included as a release asset.

## Try Diwani

After installing native dependencies and the tagged source or wheel:

```bash
arabic-calligraphy render --text "العلم نور" --style diwani --size 1400x500 --font-size 180 --output diwani.svg
arabic-calligraphy render --text "أهلا وسهلا" --style diwani --size 1400x500 --font-size 160 --output diwani.png
arabic-calligraphy poster --text "اللغة العربية" --style diwani --output diwani-poster.png
```

To install the tagged source, clone `https://github.com/akin-demir/arabic-calligraphy-skill.git` with `--branch v0.1.0-rc.2`, create a Python 3.11+ virtual environment, then run `python -m pip install .`. On Debian/Ubuntu, native packages are libpango-1.0-0, libpangocairo-1.0-0, libcairo2, libfontconfig1 and libharfbuzz0b. Authentication is required if the repository is still private. Verify downloaded assets together with `sha256sum -c SHA256SUMS`.

## Important Diwani boundaries

**PNG and outlined SVG only; no combining marks/harakat.** The original font's fsType=2 embedding flag is retained and PDF export is refused. The font lacks GPOS, so vocalized input is refused rather than given unverified mark positioning. Choose Naskh for marked text and PDF documents. This does not remove PDF support from the existing three styles.

This is not a Diwani Jali engine or a custom Al Jazeera-style interwoven logo composer. Its actual output is baseline font typography. Examples are produced by the real renderer, not an image model. No expert calligrapher approval is claimed.

## Existing PDF limitation

PDF-001 remains: raw Arabic extraction/search/copy is reader-dependent for the existing PDF workflows. Source mapping and embedding tests pass, but exact raw extraction still blocks a stable release. RC2 is authorized for testing with this limitation disclosed. RC1 is unchanged.

## Uploading the skill to Claude or ChatGPT

Upload `arabic-calligraphy-skill-rc2.zip` through the product's custom-skill interface if available. Enable code execution where required. The upload does not guarantee that its execution environment provides native Pango/Cairo or can install them. If execution is blocked, the skill must report that error, not generate a lookalike using another font. Direct web-host rendering is still unverified.

## Plan for RC3

Improving Diwani mark positioning/embedding requires a legally and technically suitable font revision or another vetted font. Diwani Jali and custom logo composition remain separate work.
